# VoteChain - Blockchain-Based Voting System (Group 19)

Tamper-proof digital voting for **local elections** with **zero-knowledge proofs** for voter anonymity and tallying.

**Stack:** Solidity (smart contracts) | Polygon (Amoy testnet / EVM chain) | React + Web3.js (frontend) | circom + snarkjs (Groth16 ZK proofs) | Hardhat (tests and deployment)

## What it does

1. The election office adds candidates and registers eligible voters. Voters create a secret credential **in their own browser**; the office only receives a *commitment* (a Poseidon hash), never the secret.
2. When voting starts, the contract stores the **Merkle root** of all commitments.
3. A voter proves in zero knowledge: *"I know a secret whose commitment is in the Merkle tree, and this one-time nullifier belongs to it"*, without revealing which voter they are.
4. The contract verifies the Groth16 proof, rejects reused nullifiers (double voting), and increments the candidate's tally.
5. Anyone can audit: rebuild the Merkle root from the public commitments, recount `VoteCast` events and compare with the published tally.

```
 Browser (React + Web3.js)                         Polygon / EVM chain
 +-------------------------------+                +----------------------------+
 | create credential (secret)    |                |  VoteChain.sol             |
 | build Merkle tree (Poseidon)  |   castVote()   |   - candidates, phases     |
 | snarkjs: generate ZK proof ---+--------------->|   - Merkle root            |
 | MetaMask signs transaction    |                |   - nullifier mapping      |
 +-------------------------------+                |   - tally + events         |
                                                  |  Groth16Verifier.sol       |
                                                  |   (generated by snarkjs)   |
                                                  +----------------------------+
```

## Project structure

```
contracts/VoteChain.sol          election logic (phases, nullifiers, tally, events)
contracts/Groth16Verifier.sol    verifier generated from the circuit by snarkjs
circuits/vote.circom             ZK circuit: membership + nullifier + candidate binding
lib/zk.js                        Node helpers (Poseidon, Merkle tree, proof generation)
scripts/setup-zk.js              compile circuit, dev trusted setup, export verifier
scripts/deploy.js | seed.js      deploy (local or Amoy) and seed demo data
scripts/demo-cli.js              full election in the terminal (backup demo)
test/VoteChain.test.js           12 tests using REAL zero-knowledge proofs
frontend/                        React + Web3.js app (Vite)
build/ and frontend/public/zk/   circuit wasm, proving key (zkey), verification key
```

## Quick start (local)

Requires Node.js 18 or newer and MetaMask in the browser.

```bash
npm install
npm test                      # 12 tests with real proofs (about 15 s)
npm run demo:cli              # whole election in the terminal

# Full app
npm run node                  # terminal 1: local blockchain (keep running)
npm run deploy:local          # terminal 2: deploy contracts
npm run seed                  # 3 candidates + 5 demo voters -> demo-credentials.json
npm run frontend:install
npm run frontend              # open the printed URL (usually http://localhost:5173)
```

**MetaMask (local demo):** add network `http://127.0.0.1:8545`, chain id `31337`, and import Hardhat account #0 (the admin):
`0xac0974bec39a17e36ba4a6b4d238ff944bacb478cbed5efcae784d7bf4f2ff80` - this is a **public test key, never use it on a real network**.
The app offers to add/switch the network automatically.

If your network blocks the Solidity compiler download, run commands with `USE_SOLCJS=1` (uses the `solc` npm package).

## Demo script for the viva (about 3 minutes)

1. Open the app, connect the admin wallet. Show phase 1 (Registration) and the candidates created by `npm run seed`.
2. Election office tab: click **Start voting**. Mention: the Merkle root of voters is now on-chain.
3. Vote tab: paste a credential from `demo-credentials.json` -> Load -> choose a candidate -> **Generate proof and vote**. Point out proof generation happening locally.
4. Try to vote again with the same credential: the contract rejects it (`NullifierAlreadyUsed`).
5. Results and audit tab: show the tally, then **Verify voter-list Merkle root** (turns green). Show the anonymous vote table: only nullifiers and candidates, no identities.
6. End voting from the election office tab. Show the final result.

Backup: `npm run demo:cli` prints the same story in the terminal.

## Security model and honest limitations

- **Integrity:** votes are only stored through the contract; there is no function to edit or delete votes.
- **Anonymity:** the proof reveals only a nullifier, never the voter's commitment or identity. The sender address of the transaction is still public on any blockchain, so use a fresh wallet or a relayer for stronger anonymity.
- **Double voting:** one credential produces one nullifier per election; reuse reverts.
- **Eligibility:** identity checking happens *offline* at registration; the chain enforces one vote per registered credential.
- **Admin trust:** the admin cannot see or change votes, but publishes the Merkle root. Anyone can recompute it from public commitments (the Audit button does this). Production should use an on-chain incremental Merkle tree and a multisig admin.
- **Trusted setup:** `npm run zk:setup` runs a single-contributor development ceremony. A real election needs a multi-party ceremony.
- **Not covered:** coercion resistance and vote buying (see MACI), voter device malware, legal approval, large-scale load testing, and a professional smart-contract audit.
- Web3.js is used as required by the project brief; its maintainers announced sunsetting in 2025, so a production version should migrate to ethers.js or viem.

## Regenerating the ZK artifacts

```bash
npm run zk:setup   # recompiles circuit, new keys, rewrites contracts/Groth16Verifier.sol
```
If you change the circuit or tree depth (`TREE_DEPTH` in the contract, `DEPTH` in `lib/zk.js` and `frontend/src/zk.js`), re-run setup, redeploy, and run the tests.
